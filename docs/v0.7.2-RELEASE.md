# v0.7.2 - Predictive WAIT safety and diagnostic cleanup

This patch fixes two issues found in live use after v0.7.1.

## WAIT now means PAC OFF immediately

When the adaptive thermal planner decides that the current trajectory is sufficient, `WAIT` now stops the heat pump immediately.

A learning or certified-temperature cycle is never allowed to justify continued heating. If a temperature stabilization is already in progress, Pool Manager can keep the pump circulating at the configured reference speed, but the PAC remains off.

Expected sequence:

```text
WAIT
  -> PAC Off immediately
  -> optional pump-only 70% certified measurement
  -> thermal model refreshed
  -> PAC remains Off unless a later plan genuinely requests PREHEAT/PRESERVE/MAINTAIN
```

## Clean predictive diagnostic sensor

The AppDaemon virtual predictive sensor now replaces its attribute set instead of merging with the previous one. This removes stale pre-v0.7 fields that Home Assistant could retain after an upgrade, including:

- `schedule`
- `heating_slots`
- `ready_by`
- `swim_datetime`
- other obsolete slot-planner attributes

## Clearer measurement wording

The predictive measurement state is now displayed as:

```text
🌀 Stabil. mesure température
```

No Home Assistant helper or AppDaemon YAML migration is required.
