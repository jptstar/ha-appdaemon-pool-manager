# v0.10.2 — Physical power-flow debug

v0.10.2 makes the power debug match the installation's physical energy flows instead of exposing the controller's internal surplus value.

## Debug output

With all measurements available, the helper now uses this stable order:

```text
Pompe 516W réel | PAC 1624W | Réseau 1115W | Réinjection 0W | Solaire 2313W
```

`Réseau` is positive grid import. `Réinjection` is positive grid export. Pump power remains marked `réel` or `estimé`. Missing configured inputs are displayed as unavailable rather than as credible zeroes.

## Configuration

The production mapping that motivated this release is:

```yaml
entity_grid_import_power: sensor.shelly_arrivee_electrique_conso_inst
restitution_inst: sensor.restitution_reseau_inst
restitution_inst_mode: export_positive
entity_pv_power: sensor.production_solaire_conso_inst_positif
entity_pac_conso: sensor.shelly_pac_piscine_conso_inst
entity_pompe_conso: sensor.shelly_pompe_filtration_piscine_conso_inst
entity_debug_w: input_text.piscine_debug_w
```

Existing single-sensor configurations remain supported. The separate import entity is optional.

## Control correction

When separate positive import and restitution entities are configured, signed grid power is calculated as import minus restitution. Grid export is already measured after PAC, pump and household consumption, so PAC power is no longer subtracted a second time from the available export.

## Validation

- Separate import and restitution readings produce the correct signed grid result.
- Import and export debug values remain independent and non-negative.
- Pump, PAC, grid, reinjection and solar values appear in the requested stable order.
- Missing required inputs remain visibly unavailable.
- Legacy positive-export and signed-grid configurations retain their existing compatibility paths.
