# v0.8.3 — Bounded temperature calibration and clean Turbo handover

This patch fixes two issues found during live use of predictive pool heating and includes the new bathing-score sensor prepared after v0.8.2.

## Temperature calibration can no longer run forever

Certified water-temperature calibration is still based on the normal `tempo_eau` circulation duration and a temporary minimum pump speed of 70% by default.

v0.8.3 makes the calibration clock monotonic:

```text
reference speed not reached yet
    -> keep requesting the temporary minimum
    -> do not start the calibration timer

reference speed confirmed
    -> start the tempo_eau timer once

later transient speed report below 70%
    -> re-command the minimum
    -> DO NOT restart the timer
```

This fixes the case where repeated speed telemetry below the reference threshold could continually reset the start time and leave Home Assistant showing "measurement in progress" for hours.

The calibration is also bounded:

- default grace period to establish or finish a measurement: **300 s**;
- if `fin_tempo` never validates or the physical water probe remains unavailable, the measurement is released after `tempo_eau + 300 s`;
- after a failed calibration, Pool Manager continues from its best available temperature estimate and waits **900 s** before trying certification again.

Optional settings:

```yaml
chauffage_predictif_mesure_timeout_grace_s: 300
chauffage_predictif_mesure_retry_s: 900
```

No new Home Assistant helper is required.

## Measurement progress is visible

The predictive status sensor now exposes:

- `measurement_requested_at`
- `measurement_elapsed_seconds`
- `measurement_remaining_seconds`
- `measurement_phase` — `raising_flow` or `stabilizing`

These attributes can be used directly in Mushroom cards to show a real countdown instead of an open-ended "measurement in progress" message.

## Forced Turbo -> Automatique handover is immediate

Leaving `Turbo • 1 h`, `Turbo • 6 h`, or another forced Turbo duration now:

1. cancels the Turbo timer;
2. immediately releases the physical PAC preset back to **Smart**;
3. recalculates the automatic/predictive strategy;
4. allows MPC to select Turbo again only if the new plan actually requires it.

This prevents the inconsistent state where the dashboard reported `Préchauffage • Smart` while the real heat pump was still running in Turbo.

If Automatique requires a fresh certified temperature before making the final heating decision, the PAC is now stopped during that pump-only calibration. Once the measurement finishes, MPC recalculates and restarts the PAC only in the preset it actually selected.

## Bathing-score Home Assistant sensor

v0.8.3 also publishes the virtual sensor:

```yaml
sensor.piscine_score_baignade
```

Its state is the selected bathing opportunity's `usage_score`. Attributes include:

- `minimum_score`
- `date`
- `usage_score`
- `weather_score`
- `strategic_score`
- `weekend`
- `usage_window`
- `confidence`

The default threshold remains **55**.

## Compatibility

No mandatory Home Assistant helper migration is required. Existing configuration continues to work; the new calibration timeout/retry settings are optional and have safe defaults.
