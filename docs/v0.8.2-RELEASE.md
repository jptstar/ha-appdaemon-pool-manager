# v0.8.2 — Temperature calibration, cover-aware MPC and HA log sensor

This patch refines the adaptive thermal measurement path after live testing.

## Temperature calibration no longer loops

Pool-water temperature stabilization is now tied to a real pump run instead of behaving like an independent long-running strategy.

A new run that needs a certified temperature uses a short calibration window only. Once calibration finishes, Pool Manager immediately returns pump-speed authority to the normal automatic strategy.

## 70% is a calibration minimum, not a fixed speed

`chauffage_predictif_mesure_vitesse_pct` remains **70% by default** because lower-flow pipe readings are not considered representative enough for certified MPC/learning data.

During calibration:

```text
pump < 70%  -> temporarily raise to 70%
pump = 70%  -> keep 70%
pump > 70%  -> keep the existing higher speed
```

The full `tempo_eau` calibration delay starts only once the pump has actually reached at least the configured certified minimum.

After the certified measurement is obtained, the temporary minimum is released and normal automatic speed control resumes.

## Cover-aware MPC reacts immediately

The configured pool-cover entity is already part of the thermal model:

- passive losses are learned separately according to real cover state;
- a passive-learning interval is rejected if the cover changes during the sample;
- future overnight calculations use `chauffage_predictif_volet_nuit_prevu`, defaulting to `closed` when a cover entity is configured.

v0.8.2 also makes cover changes immediately reactive: opening or closing the cover now triggers a Pool Manager/MPC recalculation instead of waiting for the periodic refresh.

The predictive status sensor exposes:

- `current_cover`
- `expected_night_cover`

## Home Assistant Pool Manager log entity

Pool Manager now mirrors the dedicated AppDaemon `piscine_log` stream into a virtual Home Assistant sensor:

```yaml
entity_pool_manager_log: sensor.pool_manager_log
```

No Home Assistant helper needs to be created.

The entity provides the latest event as its state and exposes attributes including:

- `timestamp`
- `category`
- `message`
- `history` — the last 20 events
- `history_size`

Events are grouped into useful categories such as `MPC`, `PAC`, `POMPE`, `MESURE`, `VOLET`, `SÉCURITÉ` and `SYSTÈME`.

## Compatibility

No mandatory Home Assistant helper migration is required.

Existing installations may optionally add the explicit YAML entry for `entity_pool_manager_log`; when omitted, Pool Manager uses `sensor.pool_manager_log` by default.
