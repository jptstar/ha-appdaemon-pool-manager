# v0.7.1 - Certified adaptive thermal decisions

Pool Manager v0.7.1 turns the predictive heating engine into a decisive, self-learning thermal controller.

## Certified pool temperature

The thermal model no longer assumes that any flowing-water sensor value represents the whole pool.

- 47% remains the normal hydraulic low limit.
- A temperature is certified for learning only after the pump has mixed at 70% for 15 minutes by default, followed by a short stability check.
- `mem_temp` and low-flow/stale pipe readings never train the model.
- Important heating decisions first request a certified measurement when the current thermal reference is too old.
- Normal filtration is reused for certification whenever possible instead of starting an unnecessary measurement cycle.

## Self-learning

The persistent model now learns from clean, certified samples:

- Smart/Turbo water-temperature gain in °C/h by outdoor-temperature range;
- average PAC electrical power and derived kWh/°C when available;
- passive overnight loss from the last certified temperature before the long stop to the first certified temperature after the next proper mixing cycle;
- cover state and water/air temperature difference for passive losses.

PAC activity or a cover-state change rejects a passive-loss sample. Learned data survives AppDaemon restarts and HACS updates.

## Daily decisions instead of heating schedules

The planner exposes one clear action:

- `WAIT`: no useful heating required today;
- `PRESERVE`: protect the recoverability floor only;
- `PREHEAT`: heat today only to the thermal trajectory target;
- `MAINTAIN`: selected bathing day, recover/hold the requested water target.

A good day several days ahead no longer means “heat to 30 °C now”. Pool Manager calculates the minimum water temperature needed today so future Smart capacity, learned losses and the remaining weather window can still reach the final target.

Smart is preferred when it can keep the trajectory. Turbo is selected only when Smart has insufficient remaining capacity. Night heating is exceptional and only continues until the trajectory is restored.

## Weather and real usage

- Strategic daily weather remains available up to 15 days.
- Hourly weather is used near-term when the provider supports it.
- Weekday bathing quality focuses on approximately 16:00-20:00.
- Saturdays and Sundays receive additional usage priority.
- A marginal early day can be skipped for a much better nearby opportunity.
- A weather-friendly day is rejected if the learned installation cannot physically recover the pool in time.

## Summer and end of season

The same engine is used in Automatique and Fin de saison • Smart.

Warm summer weather naturally keeps the thermal trajectory close to the requested water temperature. During several poor days, the PAC can stop above the recoverability floor. Near autumn, the controller lets the water drift further, targets useful bathing windows, and preheats only when the learned thermal capacity says it is time.

`brassage_nuit_intelligent: false` remains independent. Periodic night mixing stays disabled, while an exceptional pump + PAC night recovery can still run when the thermal trajectory genuinely requires it.

No mandatory Home Assistant helper migration is required. New predictive parameters are optional and have safe defaults.
