# v0.9.0 — Full-horizon predictive heating

v0.9.0 expands Pool Manager's adaptive thermal MPC from a single next-bathing target to a complete multi-window plan across the available weather horizon (up to 15 days).

## Full-horizon comfort planning

Pool Manager now keeps every credible bathing window in the same optimization instead of stopping at the first useful day.

The planner can therefore:

- prepare an early bathing day;
- look beyond it to later good-weather windows;
- deliberately let the pool cool through poor-weather gaps when that saves energy;
- restart heating at the most efficient time before the next useful window;
- preserve only the thermal reserve required to keep future comfort targets recoverable.

The plan remains receding-horizon: only the current decision is executed, and the full plan is recalculated when weather, certified pool temperature or learned thermal data changes.

## Dynamic recoverability floor

Each day of the MPC plan now carries a `recoverability_floor`: the minimum water temperature from which the remaining optimized schedule can still reach all retained bathing targets.

This makes the strategy adaptive through bad-weather periods instead of blindly maintaining the normal setpoint.

A small thermal-storage margin of up to 1 °C above the normal target is allowed in the optimizer when carrying heat from an efficient warm daytime window across a short poor-weather interval is cheaper than reheating later.

The configured absolute minimum water temperature remains a hard constraint.

## Multiple bathing opportunities and weekend preference

The forecast now exposes all retained bathing dates through `swim_dates` and `swim_opportunities`.

Weekends are preferred, not forced. The new optional setting:

```yaml
chauffage_predictif_bonus_weekend: 10
```

adds a usability preference before the bathing-score threshold, while the minimum outdoor bathing temperature remains mandatory. A cold or clearly unsuitable weekend is therefore not selected simply because it is Saturday or Sunday.

## Richer Home Assistant forecast plan

Each predictive forecast / MPC row can now expose:

- `swim`
- `primary_swim`
- `heating`
- `preheat`
- `mpc_action`
- `mpc_purpose`
- `mpc_target_date`
- `recoverability_floor`
- `mpc_heat_hours`
- `mpc_day_heat_hours`
- `mpc_night_heat_hours`
- `mpc_preset`
- `mpc_energy_kwh`
- predicted water temperature at start, daytime end and day end

The predictive sensor also exposes:

- `mpc_horizon_energy_kwh`
- `mpc_next_swim_energy_kwh`
- `swim_dates`
- `swim_opportunities`

This allows dashboards to display Pool Manager's actual plan instead of recreating planning logic in Jinja.

## Live countdowns

Forced Turbo now has a Pool Manager-owned deadline and publishes:

- `forced_heating_ends_at`
- `forced_heating_remaining_seconds`

The countdown no longer depends on Home Assistant timer `remaining`, which is not a live countdown. After an AppDaemon restart, `timer.finishes_at` is used as a fallback.

Certified temperature stabilization continues to expose:

- `measurement_remaining_seconds`
- `measurement_phase`

so both important countdowns can be displayed directly by the dashboard.

## Energy strategy

The full-horizon MPC still minimizes predicted PAC electrical energy using:

- learned Smart/Turbo heating rates;
- learned PAC electrical power;
- outdoor-temperature-dependent PAC performance;
- learned passive losses;
- water/air temperature difference;
- expected night cover state;
- a Turbo penalty;
- a larger night-heating penalty.

Daytime-only solutions are searched first. Night heating is admitted only when the same multi-window comfort plan cannot otherwise remain feasible.

This release does not require a photovoltaic-production forecast entity. Existing real-time solar-surplus control remains independent; a dedicated future PV-production forecast can be added later without changing the thermal-plan data model.

## Compatibility

No new Home Assistant helper is required.

Existing predictive configurations remain valid. The only new tuning option is optional:

```yaml
chauffage_predictif_bonus_weekend: 10
```

The previous trajectory planner remains available with `chauffage_predictif_mpc: false`.
