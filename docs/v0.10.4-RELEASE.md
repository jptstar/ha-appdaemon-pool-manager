# v0.10.4 — Observable thermal learning and physical PAC shutdown

v0.10.4 closes the two remaining gaps found in the real Home Assistant
histories: thermal learning could run without producing an accepted sample, and
filtration could be released while the PAC climate entity was already `off` but
the compressor still consumed several hundred watts.

## Thermal learning

- Predictive heating now waits for the first successful certified water
  measurement of the day. A failed calibration remains bounded and retries, but
  no longer lets the PAC contaminate the overnight reference in the meantime.
- PAC-gain learning starts from that fresh certification. After at least
  `chauffage_predictif_apprentissage_min_s`, Pool Manager stops the PAC, keeps
  circulation active and certifies mixed pool water before accepting the gain.
- This learning interruption is limited to once per day and its timestamp is
  persisted across AppDaemon restarts.
- Accepted and rejected PAC-gain/night-loss samples are written to
  `sensor.pool_manager_log` and summarized on
  `sensor.piscine_chauffage_predictif` through `heating_learning_samples`,
  `night_loss_learning_samples`, `last_heating_learning_at` and
  `last_learning_event`.

## PAC shutdown safety

Post-circulation is now tied to physical PAC power. After the normal minimum
delay, filtration continues until PAC power has remained below the configured
active threshold for 30 seconds. A 180-second maximum keeps the behavior
bounded if the meter or PAC state is stuck. This also applies when the climate
entity already reports `off` while physical consumption is still present.

```yaml
pac_post_circulation_s: 60
pac_post_circulation_stable_s: 30
pac_post_circulation_max_s: 180
```

## Optional PAC temperature diagnostics

These installation-specific entities add physical temperatures and
`pac_water_delta_c` to the existing predictive status sensor. They do not
replace `temperature_eau` and no new Home Assistant helper is required.

```yaml
temperature_eau: sensor.smart_next_water_temperature
entity_pac_inlet_temperature: sensor.pro_elyo_touch_inlet_water_temperature
entity_pac_outlet_temperature: sensor.pro_elyo_touch_outlet_water_temperature
entity_pac_ambient_temperature: sensor.pro_elyo_touch_ambient_temperature
chauffage_predictif_apprentissage_mesure_hors_pac: true
```

## Compatibility and validation

- Existing Home Assistant entity IDs, input-select values and virtual sensors
  are unchanged.
- The pump still follows solar/grid arbitration during normal operation. During
  PAC demand it keeps the hydraulic minimum (47% on the documented setup) and
  may rise only when surplus or the daily quota justifies it.
- All 152 automated tests pass, including morning-calibration gating,
  once-daily mixed-water learning and residual PAC-power post-circulation.
