# v0.10.3 — PAC anti-short-cycle protection

v0.10.3 corrects the short heating cycles identified from real Home Assistant history after v0.10.2. Predictive MPC decisions can no longer stop a compressor seconds after it actually starts and then request another start a few minutes later.

## Compressor protection

- `pac_min_on_s` defaults to 900 seconds and is measured from physical PAC power, not from the earlier Home Assistant `Heat` command.
- `pac_min_off_s` defaults to 300 seconds before a managed restart.
- A deferred predictive stop keeps the pump circulation demand active.
- A renewed heat decision cancels an obsolete deferred stop.
- Forced stop, heating disable, Hors Gel and circulation fail-safe stops remain immediate.

The settings are optional and preserve existing Home Assistant entity IDs and selector options:

```yaml
pac_min_on_s: 900
pac_min_off_s: 300
```

## Energy behavior

When PAC activity and grid import are present, the pump still falls back to the configured minimum PAC circulation speed, normally 47%. Solar surplus and critical daily quota remain allowed to request a higher speed.

Small negative PAC or photovoltaic meter noise is now displayed as `0 W` in the physical-power debug.

## Validation

- Predictive stops are deferred during the real compressor minimum runtime.
- Stops execute after the minimum runtime expires.
- Safety stops bypass the runtime hold.
- Managed restarts respect the minimum off time.
- Physical PAC power starts the runtime clock.
- Pump circulation remains protected during a deferred stop.
- All 147 automated tests pass.
