# v0.10.0 — Explicit core coherence

v0.10.0 is an internal-coherence release. It preserves the Home Assistant surface while making control priority reviewable and testable.

## What changes

- Domain initialization is an explicit pipeline owned by the AppDaemon entry point.
- Domain components no longer expose homonymous methods whose behavior depends on Python MRO order.
- PAC circulation demand and chlorination authorization are explicit compositions with documented priority.
- Journal formatting/publication lives outside equipment-control policy.
- Fixed-time daylight fallbacks, energy stability, quota recovery and night mixing have distinct internal owners.
- Architecture tests reject duplicate component method ownership and unintended cooperative `super()` chains.
- The canonical v0.9.1 Home Assistant entity mapping is frozen as a compatibility test.

## Compatibility

No Home Assistant entity, AppDaemon configuration key, heating selector option, virtual sensor, timer, input helper, service call, or thermal-learning persistence filename is renamed. Existing v0.9.1 configuration remains valid without migration.

## Required validation before publication

- Run the complete Python suite.
- Compile every AppDaemon module.
- Load the canonical example configuration in the target AppDaemon/Home Assistant environment.
- Exercise forced stop, Hors Gel, PAC pump-first start, PAC flow loss, calibration interruption/restart, and chlorinator shutdown.
- Observe at least one normal filtration/quota cycle and one MPC recalculation without direct pump-command conflicts.
- Only then create the `v0.10.0` tag and GitHub/HACS release.

This branch intentionally contains no publication step or release tag.
