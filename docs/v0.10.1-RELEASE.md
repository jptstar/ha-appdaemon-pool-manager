# v0.10.1 — Reliable solar-surplus input

v0.10.1 fixes solar-surplus control for installations whose Home Assistant grid entity reports exported power as a positive value.

## Fixed

- `restitution_inst` now supports both positive-export sensors and signed net-grid sensors.
- The default `auto` mode recognizes entity ids containing `restitution`, `export` or `injection` as positive export while preserving signed behavior for generic grid-power entities.
- Missing, `unknown`, `unavailable` and non-numeric grid states no longer appear as a valid `0 W` reading.
- Solar arbitration is suspended while the required grid measurement is unavailable.
- The pool journal records the electrical-input fault once and records recovery when valid data returns.
- The optional photovoltaic-production entity is documented for the existing debug output.

## Configuration

Existing configurations remain valid. For the installation that exposed this issue, the relevant mapping is:

```yaml
restitution_inst: sensor.restitution_reseau_inst
restitution_inst_mode: auto
entity_pv_power: sensor.production_solaire_conso_inst_positif
entity_pac_conso: sensor.shelly_pac_piscine_conso_inst
entity_pompe_conso: sensor.shelly_pompe_filtration_piscine_conso_inst
entity_debug_w: input_text.piscine_debug_w
```

Use `restitution_inst_mode: export_positive` or `restitution_inst_mode: net_signed` only when the entity name does not describe its sign convention clearly.

## Validation

- Positive restitution is normalized to negative net-grid export before surplus calculation.
- Signed grid import and export preserve their existing behavior.
- Explicit configuration overrides automatic entity-name detection.
- An unavailable grid sensor remains unavailable and triggers fail-safe handling instead of becoming zero.
- The full Python suite, module compilation and repository checks pass from the release commit.
