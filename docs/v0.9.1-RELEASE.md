# v0.9.1 — Protected calibration and readable pool journal

v0.9.1 focuses on two operational problems observed on a real installation: certified pool-temperature measurements could be interrupted by normal energy arbitration, and the central Home Assistant pool journal was too noisy to understand what Pool Manager was actually doing.

## Protected certified temperature calibration

Once a certified pool-temperature measurement has started, normal solar/grid/quota optimization can no longer stop the pump just because house consumption is high or solar surplus is weak.

The priority order is now:

1. safety / forced stop / Hors Gel;
2. active certified temperature calibration;
3. PAC / MPC needs;
4. filtration quota;
5. solar and grid-import optimization.

The PAC remains off during a decision calibration. The pump only provides the circulation required to measure the pool correctly.

## Any real pump stop restarts the measurement

A pipe sensor in a technical room can be very different from the actual pool after a stop. If the pump really stops during a calibration, the in-progress sample is invalidated.

The next attempt restarts the complete hydraulic delay from zero. A short pump interruption can no longer inherit an old calibration timer and certify a transient pipe temperature a few seconds after restart.

## 15 min circulation + stable probe

Reaching `tempo_eau` is no longer sufficient by itself.

After hydraulic mixing, the physical probe must remain stable for:

```yaml
chauffage_predictif_mesure_stabilite_s: 120
chauffage_predictif_mesure_variation_max_c: 0.15
```

Defaults are therefore:

- normal hydraulic circulation delay from `tempo_eau` (typically 15 min);
- then 2 min of sensor stability;
- maximum variation 0.15 °C during that stability window.

A larger variation restarts only the final stability window.

The predictive status sensor now exposes:

- `measurement_remaining_seconds`
- `measurement_phase`
- `measurement_stability_seconds`
- `measurement_max_variation_c`

The countdown covers both circulation and final sensor stability.

## Central pool event journal

`sensor.pool_manager_log` remains the single central chronological journal for important pool events.

v0.9.1 changes it from a noisy telemetry mirror into an event journal. It now keeps meaningful events such as:

- pump start / stop;
- calibration start / interruption / certification;
- PAC start and real preset changes;
- meaningful MPC plan changes;
- cover events;
- thermal learning;
- electrolysis and safety events.

Consecutive identical events are ignored.

Repeated messages such as an already-running PAC being “started” every 30 seconds are no longer journaled.

## French user-facing journal

Internal tokens are normalized before publication. Home Assistant no longer needs to display strings such as:

- `end_season`
- `MAINTAIN`
- `PREHEAT`
- `WAIT`
- `Heat/Smart`
- `startup_calibration`

The journal uses French user-facing wording instead.

## Existing status helpers remain

The existing helpers are not removed:

- `message_filtration_piscine`
- `message_filtration_piscine_detail`
- `piscine_debug_w`

They remain live current-state / diagnostic outputs for compatibility.

The virtual `sensor.pool_manager_log` is the chronological history of important events.

The event history defaults to 50 entries and can be adjusted with:

```yaml
pool_manager_log_history_size: 50
```

## Compatibility

No new Home Assistant helper is required.

Existing configurations continue to work. The stability settings are optional and default to the values above.
